# System Prompt: Build `Conduit` Open-Source Engine (Autonomous CLI Edition)

## Executive Summary & Mission
You are building `Conduit` (`xlor1009/conduit`), an open-source, self-hosted CLI tool that automatically performs breaking API updates in consumer repositories.

Instead of relying on a centralized static packet registry, Conduit operates as a fully autonomous agent. When `conduit run` is executed:
1. It inspects version jumps in local dependency manifests.
2. It dynamically scrapes external vendor migration context (changelogs, GitHub releases, docs). (It can also be given the changelogs, release, docs so a user can create a Migration Packet)
3. It synthesizes a temporary or locally-cached Migration Packet (`conduit-packet.json`) containing AST codemod rules.
4. It applies AST structural transforms and runs a local test-verification and LLM self-correction loop against native unit tests (`pytest`, `npm test`).
5. It opens a fully verified Pull Request.

---

## E2E Execution Flow

1. [Detect Diffs in API Repo + other sources(ie: changelogs,docs)]
   - Parse package.json, requirements.txt, pyproject.toml, go.mod.
   - Identify upgraded SDKs (e.g., openai v0.28.0 -> v1.0.0).
	1. Lockfile Git Diff (Dependency Isolation)

	Conduit checks git changes on manifest/lockfiles (package-lock.json, poetry.lock, requirements.txt).

	If 50 dependencies exist but only openai changed from 0.28.0 to 1.0.0, Tier 1 ignores the other 49 packages entirely.

	2. Fast String/Regex Pre-Filtering (File Pruning)

	Before building AST trees for your project, Conduit runs a lightweight ripgrep-style text search across the repo.

	It checks for basic import statements matching the changed package (e.g., import .* from ['"]openai['"] or from openai import).

	Files without those import strings are instantly dropped. If only 3 files out of 500 import openai, only those 3 files move forward.

	3. Package Export Delta (Package-Only Scope)

	Conduit compares the exported type/API declarations (.d.ts files, __all__, or type stubs) between openai@0.28.0 and openai@1.0.0.

	It extracts only the specific symbols that were renamed, removed, or changed in that single package update.

	4. Hard Directory Exclusions

	Tier 1 strictly ignores node_modules/, vendor/, dist/, .git/, and build artifacts by default.

	The Resulting Execution Pipeline
	[ Git Diff on Lockfile ] ──► Identifies 1 updated package (e.g., `openai`)
			   │
			   ▼
	[ Fast Grep Pre-filter ] ──► Prunes repo from 500 files down to 3 matching files
			   │
			   ▼
	[ Export Delta Check ]   ──► Extracts changed API symbols for `openai`
			   │
			   ▼
	[ Pass to Tier 2 ]       ──► Builds AST ONLY for those 3 files and symbols
	
1.1 [Autonomous Migration Packet Synthesis]
   - Check local cache (`./.conduit/packets/`) for an existing packet.
   - If missing:
     a. Fetch external context via GitHub Release API or web doc search for target package & version jump.
     b. Prompt the local/configured LLM to generate a `conduit-packet.json` schema containing AST transformation patterns and migration rules.
     c. Cache the generated `conduit-packet.json` to `.conduit/packets/`.

2. [Deterministic AST Refactoring Engine in Client Repo]
   - Parse project files and apply the synthesized AST codemod rules (e.g. updating imports, instantiating client objects, updating call chains) from the conduit package created from step 1.1.

4. [Native Test Suite Execution]
   - Detect test runner (`pytest`, `npm test`, `jest`, `go test`).
   - Run existing test + create new if needed. 
   - Run native test suite. If all pass -> Skip to PR Generation.

5. [LLM Self-Correction Loop]
   - If tests fail, capture error stack traces and failing source files.
   - Send code + trace + packet context to LLM (OpenAI, Anthropic, or local Ollama).
   - Apply generated patch and re-run tests (up to 5 retries).

6. [Git Branching & PR Generation]
   - Stage changes, commit to branch `conduit/upgrade-{package}-{version}`, and open PR with execution logs.
